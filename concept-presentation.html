03 · Relevance scoring
Only shared terms contribute
Repeated query words collapse into a set
query: "Python Python!"
query_terms: {"python"}
Set intersection selects words present in both the query and the chunk. A passage can match some query terms without matching all of them.
Empty input stays safe
An empty token set or a non-positive limit returns immediately. No-match chunks skip scoring.
03 · Relevance scoring
The score has three moving parts
Capped counts, rarity weights, and a length penalty
OperationMeaning
min(count, 3)Repetition stops helping after three
× IDFRarer matching words carry more weight
÷ √token countLong passages receive a length penalty
Illustrative one-term calculation
count = 2, IDF = 2, length = 16
score = (2 × 2) / √16 = 1
This value is a ranking heuristic. It does not express a probability that the passage answers the question.

07 · Index lifecycle

Hypothetical caller mutation
[B, A]     [counts_A, counts_B]
self.chunks = chunks retains the caller’s list. Reordering it later could pair the wrong text with its counts. zip also stops at the shorter sequence.
The current CLI constructs and searches immediately. A reusable service should protect or copy the collection.
07 · Index lifecycle
Every command rebuilds the index
Simplicity has a cost as the collection grows
Each invocation reads files, creates chunks, and initializes term statistics. Each query then scans every chunk.

08 · Determinism
Summation order can affect close scores
Stable sorting starts with stable score calculation
Matched terms form a set. Its iteration order can vary between processes, and floating-point addition has finite precision.
Illustrative full values   Display

0.81231                    0.812
Future strict reproducibility: iterate terms in a fixed order and consider math.fsum. Inspect full scores when displayed values appear equal.
